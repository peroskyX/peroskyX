# Publishing and Episode hosting

**Status:** Available on every plan; custom branding rules vary by plan  
**Primary users:** Anyone ready to make an Episode page public

## Purpose

Episode turns working pages into hosted web experiences without requiring a separate deployment system. Every plan includes an Episode-hosted address, and hosting does not consume AI credits.

## Capabilities

- Publish a new Episode website.
- Display live publishing progress while the site is being prepared.
- Retry a failed publishing attempt.
- Receive a usable hosted URL after first publication.
- Detect edits that have not yet been published.
- Update or republish an existing site.
- Unpublish a live site.
- Publish multiple pages without page-count billing.
- Remove the Episode badge on eligible paid plans.
- Celebrate and clearly confirm a successful first publication.

## How it works

1. The user reviews the page and opens the publishing surface.
2. On first publication, Episode builds and deploys the website, showing progress and any recoverable error.
3. The completed state exposes the public address.
4. Later edits remain unpublished until the user chooses update or republish.
5. Unpublish removes the live experience while preserving the working Episode so it can be revised and published again.

## Important behavior

Publishing is an explicit boundary. Editing in Agent or Studio does not silently replace what visitors currently see. The interface distinguishes a working version with unpublished changes from the live version.

An Episode-hosted URL is available without configuring DNS. Custom domains, path publishing, and badge removal have separate plan and setup requirements. Publishing itself does not spend AI credits, though creating or revising the content with AI can.
