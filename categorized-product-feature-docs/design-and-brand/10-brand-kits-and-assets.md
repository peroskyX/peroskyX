# Brand kits and assets

**Status:** Available  
**Primary users:** Brand owners, designers, agencies, and teams managing multiple brands

## Purpose

A Brand Kit gives the agent reusable design direction before it writes or builds. It centralizes colors, typography, logos, imagery, and brand completeness so generated work starts closer to the organization’s identity.

## Capabilities

- Create a kit from a blank setup, an available template, or a website scan.
- Define brand colors, typography, and logos in one place.
- Extract visible brand signals from an existing website.
- Review what extraction found before relying on it.
- Store logos, product shots, photography, and other reusable assets in the workspace library.
- Use those assets across multiple pages.
- See a completeness meter that identifies missing brand inputs.
- Maintain multiple workspace-scoped kits where the product configuration allows it.

## How it works

1. The user chooses how to start the kit: scan a site, begin blank, or use a supported template path.
2. Episode records the visual foundations and collects reusable assets.
3. The completeness view highlights gaps that could make generated work generic or inconsistent.
4. The kit is made available to agent and Studio workflows in the relevant workspace.
5. Users can continue maintaining the source values as the brand evolves.

## Important behavior

Website extraction is an accelerator, not an approval step. Sites can contain outdated colors, campaign-specific type, or low-quality logo files, so a user should review extracted values. Workspace scope matters: changing a kit can influence later work across that workspace, while existing published pages do not necessarily update until edited and republished.

Assets in the library are reusable source material. Their presence does not replace the need to verify licensing, accessibility text, crop, and suitability for a particular page.
