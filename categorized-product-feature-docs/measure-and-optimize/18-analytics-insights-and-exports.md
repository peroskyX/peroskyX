# Analytics insights and exports

**Status:** Available where the account’s analytics plan enables them; export is listed as Pro  
**Primary users:** Teams investigating changes or moving data into another workflow

## Purpose

Insights reduce the effort needed to notice meaningful movement in website performance, while exports let teams take the selected data outside Episode for reporting or further analysis.

## Capabilities

- Surface “what changed” observations in analytics.
- Present confidence context so an apparent movement is not treated as equally reliable in every case.
- Offer an AI-assisted “Fix with Episode” path from an identified issue or opportunity.
- Export analytics for a chosen date range.
- Preserve relevant filters in the export request.
- Download the resulting data for external analysis or reporting.

## How it works

The user first selects an Episode, reporting view, date range, and filters. Insights interpret that same reporting context and call attention to notable changes. Where the product offers a remediation action, the user can hand the issue to Episode rather than manually rewriting the observation as a new brief.

For export, the user opens the export dialog, confirms the date window and filters, and downloads the prepared dataset. The exported result represents the selected slice, not necessarily every event the site has ever collected.

## Interpretation and safeguards

An insight is a prompt for investigation, not proof of causation. Campaign timing, traffic mix, page edits, tracking changes, and sample size can all explain movement. Confidence indicators help communicate evidential strength but do not replace product judgment.

Before acting on “Fix with Episode,” users should confirm that the proposed change matches the actual problem and review generated output before publishing. Exports can contain commercially sensitive performance information and should be handled according to the organization’s data policy.
