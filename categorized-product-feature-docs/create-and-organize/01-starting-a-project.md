# Starting a project

**Status:** Available  
**Primary users:** Marketers, founders, designers, and content teams  
**Where it begins:** Onboarding and the Agent workspace

## Purpose

Episode avoids forcing every project to begin from a blank canvas. A user can start with an outcome, an existing design or website, a working document, or source material. The selected starting point becomes context for the agent rather than a rigid template.

## Capabilities

- **Describe the outcome:** Explain the page or campaign in plain language. The agent turns the brief into a plan, writes initial copy, and builds the page.
- **Start from an existing URL:** Supply a website so Episode can use its visible brand, tone, and structure as source context.
- **Import a Figma frame:** Connect Figma and use a frame as the initial design direction.
- **Start from Notion:** Connect Notion and select a document whose content should become a page.
- **Bring source material:** Attach documents, images, and brand assets to the request.

## How it works

1. The user chooses a starting method and provides the requested source or brief.
2. Episode gathers enough context to define what should be produced. Connected-source methods can require authorization before their content is available.
3. The agent creates a real job, then streams progress and page sections rather than returning only written advice.
4. The output becomes an Episode that can be refined in chat or opened in Studio.
5. Missing brand information can be completed through a Brand Kit before or after the first build.

## Important behavior

The starting material guides the first result; it does not lock the user into the imported structure. Users can continue prompting, edit the page directly, replace assets, or create a Take. A source may fail to import when it is private, unavailable, or the corresponding app connection has expired; the user can reconnect or attach exported material instead.
