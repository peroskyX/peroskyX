# Episodes and pages

**Status:** Available  
**Primary users:** Anyone creating or managing web experiences

## Purpose

An Episode is the durable project that contains the pages and creative work produced by the agent. Conversations can help create or modify it, but the Episode remains available independently of any one chat thread.

## Capabilities

- Browse existing Episodes from the authenticated Episodes area.
- Open an Episode in its working surfaces, including Studio, analytics, accounts, and publishing where applicable.
- Maintain multiple pages inside one Episode without a page-count meter.
- Reorder and navigate pages from Studio.
- Keep alternate page versions as Takes without overwriting the current version.
- Publish, update, republish, or unpublish the resulting website.

## How it works

1. An Episode is created by an agent build or selected from the existing collection.
2. The Episode becomes the shared container for its pages, assets, publication state, analytics, and related account-personalization work.
3. Users move between chat for instruction, Studio for direct control, and publishing for the live version.
4. Changes remain working changes until a user publishes or updates the live site.
5. Analytics and optimization views report against the published experience, subject to the account plan.

## Important behavior

Deleting a conversation does not delete the Episode created through that conversation. This separation prevents conversation cleanup from destroying product work. Publication state is also separate from editing state: the interface can identify unpublished edits and offer an update or republish action.

Episode supports multiple pages, but plan limits may govern other units such as active Episodes, usage, analytics access, custom domains, or experiments. A page is therefore not itself the billing meter described by the product catalogue.
